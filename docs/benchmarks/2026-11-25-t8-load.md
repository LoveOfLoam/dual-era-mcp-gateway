# T8 Envoy load run (2026-11-25)

This is **single-host Docker T8 evidence**, not a 500 RPS / 10-minute SLA test.

## Topology

```
loadgen 10 workers, 5s
  -> public Envoy :8080
       -> ext_authz policy
       -> ratelimit policy (Redis-backed)
       -> modern facade (Go gateway)
            -> legacy mocks
```

Envoy image: `envoyproxy/envoy:v1.40.2`. All containers run on one Windows
Docker Desktop host. No TLS in this run.

## Command

```powershell
powershell -File scripts/t8-load.ps1 -Concurrency 10 -Seconds 5
```

## Result (`docs/benchmarks/t8-load.json`)

| Metric | Value |
|---|---:|
| Requests | 15,572 |
| HTTP 200 | 15,562 |
| Errors | 0 |
| RPS | ~3,114 |
| p50 | 3.16 ms |
| p95 | 4.80 ms |
| p99 | 5.83 ms |
| max | 35.0 ms |

Durations in JSON are nanoseconds; the table converts to milliseconds. The
10 non-200 attempts were in-flight at the 5s deadline, not reported as errors.

## What this proves

- real public Envoy → ext_authz → ratelimit → modern facade path sustains
  ~3.1k RPS for 5s with 10 workers on this host;
- no 5xx/transport errors in the run;
- `scripts/t8-load.ps1` is reproducible.

## What this does not prove

- PRD target of 500 RPS for 10 minutes, p99 < 10 ms under production topology;
- SSE / long connections;
- multi-instance HA, Redis failover, xDS churn;
- TLS overhead (separate T8 TLS run covers correctness, not this load).

Do not publish this as a production SLA number.
