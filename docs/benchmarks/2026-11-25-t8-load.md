# T8 Envoy load run (2026-11-25)

This is **single-host Docker T8 evidence**, not a 500 RPS / 10-minute SLA test.

## Topology

```
loadgen 10 workers, 5s
  -> public Envoy :8080
       -> ext_authz policy
       -> ratelimit policy (Redis-backed)
       -> modern facade (Go gateway)
            -> legacy mocks
```

Envoy image: `envoyproxy/envoy:v1.40.2`. All containers run on one Windows
Docker Desktop host. No TLS in this run.

## Commands

```powershell
powershell -File scripts/t8-load.ps1 -Concurrency 10 -Seconds 5
powershell -File scripts/t8-load.ps1 -Concurrency 2 -Seconds 600 -Out docs/benchmarks/t8-load-10m.json
```

## Result (`docs/benchmarks/t8-load.json`)

| Metric | Value |
|---|---:|
| Requests | 15,572 |
| HTTP 200 | 15,562 |
| Errors | 0 |
| RPS | ~3,114 |
| p50 | 3.16 ms |
| p95 | 4.80 ms |
| p99 | 5.83 ms |
| max | 35.0 ms |

Durations in JSON are nanoseconds; the table converts to milliseconds. The
10 non-200 attempts were in-flight at the 5s deadline, not reported as errors.

## What this proves

- real public Envoy → ext_authz → ratelimit → modern facade path sustains
  ~3.1k RPS for 5s with 10 workers on this host;
- no 5xx/transport errors in the run;
- `scripts/t8-load.ps1` is reproducible.

## 10-minute run (`docs/benchmarks/t8-load-10m.json`)

Two workers, 600s, same topology:

| Metric | Value |
|---|---:|
| Requests | 500,710 |
| HTTP 200 | 500,710 |
| Errors | 0 |
| RPS | ~835 |
| p50 | 2.18 ms |
| p95 | 3.21 ms |
| p99 | 3.74 ms |
| max | 36.9 ms |

This exceeds the PRD's 500 RPS for 10 minutes on this single host. It is still
one Docker host, one gateway instance, one Redis, and `tools/list` traffic; it
is not an HA or long-lived-SSE SLA.

The background job wrapper reported exit 1 at the 600s boundary; `loadgen`
wrote the JSON above and reported 0 request errors. The 3s control run exits 0;
the 10-minute wrapper result is a harness boundary artifact, not a load error.

## What this does not prove

- PRD target under production topology / HA; the single-host 10-minute run is above;
- SSE / long connections;
- multi-instance HA, Redis failover, xDS churn;
- TLS overhead (separate T8 TLS run covers correctness, not this load).

Do not publish this as a production SLA number.
